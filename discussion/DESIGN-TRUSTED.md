# PwshMCP：可信开发会话与独立执行环境

## 核心选择

用户愿意信任模型并承担部分风险。因此默认提供通用 PowerShell，授权粒度是开发会话，不要求逐条命令、固定动词或脚本哈希审批。常驻组件管理权限和任务，每条命令用独立进程、每次启动重建环境。

## 授权和架构

- 普通权限 MCP 提交和查询；.NET Windows broker 服务管理身份、授权和状态。
- 用户主动开启“可信开发会话”，完成一次 UAC。受保护的授权程序显示实际管理员身份、整机执行能力及授权期限。
- 默认授权到当前 Windows 登录会话结束或用户主动关闭；也可设置截止时间。不默认每两小时重新确认，不因锁屏、短暂断线或命令变化而失效。
- 授权程序启动会话内管理员启动器。启动器只派生执行进程，不把所有任务交给同一个长期 PowerShell runspace。
- Agent 显式选择普通或管理员权限。普通构建仍可普通执行；不把访问拒绝自动升级重跑。
- 通用授权内允许项目脚本、虚拟环境和动态工具。工作目录是执行上下文，不是系统权限边界。
- 固定操作策略仍可用于长期机器任务，但不是日常开发必经入口。不增加模型逐条安全审核层。
- 信任绑定已登记的本地客户端和会话，不依据模型自报名称授予权限。Agent 无权批准、续期或扩大授权。
- 默认注销/重启后通用会话失效；新登录会话主动开启一次。跨注销/重启的机器执行可单独授予持久授权，但明确为 machine 身份，不默认开启，不冒充用户环境。
- 不保存管理员密码，不自动恢复 Agent 宿主。服务恢复不等于整个开发会话恢复。

## 每次启动重建环境

仅创建新进程不够：子进程默认继承父进程旧环境。每次执行必须构造独立环境块，不复制 broker、启动器或 MCP 的完整启动环境。

1. 按实际执行用户及已加载配置文件构造最新基础环境；采用 CreateEnvironmentBlock，禁止继承旧进程环境，验证系统/用户持久变量更新可见性。
2. 正确处理变量删除、名称大小写不敏感、REG_EXPAND_SZ 展开和 Windows PATH 合并规则，不能简单拼字典。
3. 覆盖顺序为：最新系统/用户基础环境 → 显式命名任务上下文 → 本次请求覆盖。支持清除覆盖和显式删除变量。
4. 将环境块、绝对工作目录及引擎路径传给新进程；默认 NoProfile/NonInteractive，需要 profile 时显式启用并在 fresh 执行时重新加载。
5. 返回实际身份、引擎路径/版本、cwd、环境采样时间和快照编号；不返回完整变量值或秘密哈希。编号只标识采样，不承诺多个配置来源具备事务一致性。

不整体继承 Agent 的旧环境，避免旧 PATH 再次覆盖新配置。Agent 专用临时变量需要显式传入。秘密可按变量名在执行时解析，不必先让模型看到值。

| 状态来源 | 行为 |
|---|---|
| Windows 系统/用户持久变量 | 下一条 fresh 命令重读，覆盖新增、修改和删除 |
| 单条命令的 $env:X、cd、函数、模块 | 仅属于该进程，默认不延续 |
| 显式命名任务上下文 | 只影响该任务，基础环境仍逐次刷新 |

命名任务上下文记录覆盖来源，可查询和清除，不自动保存整份旧 PATH。虚拟环境优先用解释器绝对路径或显式工具链设置；不能假定上一条 activate 会影响下一条独立命令。

## 可选持久会话

确实需要连续 cd、变量、函数、模块、激活环境时，Agent 显式创建独立 session。会话内保留状态，不在命令执行中强制刷新环境。

外部配置变化后可 session_reset：重新创建 PowerShell，采用新环境，明确丢失旧临时状态；只要管理员授权有效就不再次 UAC。会话不可跨任务自动共用。

已运行程序和已加载模块不能靠修改环境自动更新，需要业务重启；不承诺透明热刷新。

## 身份与并发

user-elevated 使用 UAC 实际选定的管理员身份。若凭据属于另一个账号，HKCU、profile 和环境也不同；必须显示真实来源，不能静默混合。SYSTEM 仅用于明确批准的机器任务。用户执行器失效返回 needs_session，不切换为 SYSTEM。网络凭证和映射盘需单独验证，环境重建不代表复制登录状态。

单一 broker 不等于单一执行进程或全局锁。独立任务可并发；安装器、同一服务修改、持久环境写入及后续依赖命令按明确依赖排序。依赖命令在前一操作完成后才采样环境。

## 接口与生命周期

- run：code、cwd、privilege、context、env、session、request_id、timeout，返回任务 ID。
- status / output / cancel：状态、游标输出及停止任务。
- session_open / session_close / session_reset：持久 shell 生命周期，受已有授权检查。
- context_set / context_clear：任务环境覆盖，秘密不持久化为普通文本。
- env_info：来源、采样时间、覆盖项名称，变量值默认隐藏。
- grants：只读查看授权。

未授权立即返回 needs_approval，后台只显示不抢焦点的待办。用户主动操作才触发 UAC；取消不自动重弹。授权在实际启动时检查，过期待办不因后来开窗自动执行。

同请求 ID 同内容返回已有任务，不重复执行；同 ID 不同内容拒绝。崩溃或断线无法确认效果时返回 outcome_unknown，非幂等操作先核验状态再决定重试。

撤销禁止新任务；在途按任务执行时限处理，可另选停止。停止不等于回滚，Job Object 不保证停止经系统服务启动的所有工作。

## 保留的保护与接受的风险

执行器程序、策略、高权启动链受管理员 ACL 保护；本机命名管道显式权限、拒绝远程、验证双方身份；授权控制与普通提交通道分开。PID、项目名和模型名不能单独作为凭据。

信任模型不等于可以抵抗被劫持的客户端。通用管理员脚本能影响整机、修改安全设置或持久化；到期、撤销和卸载不能清除已经发生的改动。以上是用户接受便利性时的真实风险，而非使用黑名单伪装成隔离。

日志保留身份、授权、摘要和脱敏结果，不默认保存脚本全文或完整环境。执行原文仅在受限临时区保留，完成及崩溃恢复时清理。更新需主动提权、处理在途任务、保留回退并使通用窗口失效；卸载处理任务和服务，不声称回滚系统修改。

Windows UAC 与 Agent 宿主审批分别处理；本产品不绕过宿主明确的权限限制。

## 验收

1. 同一授权会话多条不同管理员命令不重复 UAC；锁屏和短暂断连不凭空取消授权。
2. broker/MCP/启动器均不重启，修改或删除系统、用户变量后下一条 fresh 命令准确可见。
3. 安装新 CLI 或更新 PATH 后下一条命令发现工具；Agent 旧环境不覆盖新值。
4. 不同任务的 cwd、变量、venv 互不污染；显式持久会话能保留状态，reset 后更新且不重复 UAC。
5. 标准用户、不同管理员账号、SYSTEM、Administrator protection 下真实身份和环境来源准确显示，无法满足则明确失败。
6. 未授权请求不抢焦点；重复请求不重复执行；崩溃未知结果不误报成功；并发依赖、更新和卸载行为明确。

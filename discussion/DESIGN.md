## 目标

减少重复 UAC；后台请求不抢焦点；预授权范围内无人值守执行；保留清晰且可撤销的授权边界。安装授权、Windows 提权、业务操作授权和 Agent 宿主审批分别处理，MCP 不绕过宿主政策。

## 统一架构

- 普通权限 MCP：提交、查询、取输出、取消，不允许批准或延长授权。
- .NET Windows broker 服务：开机自启，LocalSystem 身份，小范围实现身份验证、策略裁决、任务状态和机器操作派发。LocalSystem 高权是明确成本，不代表所有命令以此身份执行。
- 普通用户控制入口：不抢焦点的待办提示、状态展示、撤销。无授予权限的能力。
- 受保护的 approve 程序：由用户主动启动 UAC，提权后展示服务持有的不可变请求快照，用户明确确认能力、对象、执行身份及期限后授予权限。UAC 安全桌面只确认启动程序，自定义授权页面不宣称处在安全桌面。
- 用户会话管理员 worker：approve 启动并注册，主动连接服务，执行 user-elevated 任务。会话结束时退出，失联后不启动新任务。
- 机器执行器：服务按显式机器授权派生，用于无登录会话任务；不自动把用户任务切换为 SYSTEM。

一个产品与授权模型同时覆盖两种执行身份，不作为阶段路线。

## 授权

安装后授权为空。任何授权均绑定本地身份、已登记连接、执行身份、能力、期限和策略版本；Agent 自报项目名不作为鉴权依据。

1. 结构化操作：明确动词、目标及参数，由服务端固定实现校验。用户可选择到期时间或持久授权。操作若能间接执行用户可变代码，则不能当作窄权限；例如服务启动目标、脚本配置或插件可写时，仅允许重启某服务也可能形成通用提权。
2. 审阅脚本：入口及依赖固定于管理员保护区域；用户批准的是具体管理员代码，不是安全证明。涉及用户可变代码、动态加载或无法界定的执行依赖时，按通用权限处理。持久授权必须单独主动选择，不能仅凭脚本哈希默认永久放行。
3. 通用管理员 PowerShell：明确整机修改能力；默认建议两小时，可选结束时间，不设无依据硬上限。Agent 无权续期。默认不跨重启恢复。

用户可以一次批准整个开发工作窗口，避免逐条命令审批。多个待审批请求可以集中展示，但授权只覆盖明确列出的能力及范围。工作目录是执行参数与审计信息，不能限制任意管理员脚本影响范围。

## 执行身份与无人值守

- user-elevated：使用用户经 UAC 实际选定的管理员身份，展示账号和权限；不同账号提权不能冒充原用户。配置文件、环境、HKCU、网络凭证、映射盘均需明确处理并实测，不保证与普通终端相同。
- machine：显式机器授权、无交互、无自动继承用户凭证；未登录也可执行允许跨重启的固定机器操作。
- 锁屏时不产生 UAC；已注册 worker 的执行行为需验收。注销后 user-elevated 返回 needs_session；重启后通用授权失效。
- 未来动态任务能否继续提交取决于 Agent 宿主是否恢复。服务只管理自身请求与状态，不自动恢复 Agent，也不变成通用任务调度平台。
- 安装、升级、卸载需要主动提权；日常受限持久策略无需反复 UAC；新的通用工作窗口需用户主动授权。

## 请求与故障语义

接口：admin_submit、admin_status、admin_output（游标分页）、admin_cancel、admin_grants、admin_ops。submit 返回任务 ID 和状态，不长时间等待 UAC。

状态：needs_approval、needs_session、queued、running、succeeded、failed、rejected、expired、cancelled、outcome_unknown。

- 待批准请求不进入执行队列；审批完成后复核内容、目标、期限，再入队。过期和已取消请求不得因后来扩大授权自动执行。
- 请求 ID 与请求内容绑定；同 ID 同内容返回原状态，同 ID 不同内容拒绝。
- UAC 取消仅表示未授权，保留请求，只有用户主动重试才再弹窗。
- 授权在实际开始执行时再次检查；到期拒绝新任务，在途按单独执行时限处理，不无限延续窗口。
- 撤销阻止新任务；取消尝试停止任务树。进程停止不等于回滚，也不能保证终止通过系统服务派生的工作。
- 崩溃、重启或断线后无法确认效果的任务进入 outcome_unknown，先核对实际状态，禁止自动换 ID 重跑非幂等操作。

## 安全与运维

- 程序、策略、审批快照、脚本依赖放管理员保护目录；不从用户 venv、项目目录或用户可写模块目录加载高权代码。
- 本机命名管道显式 ACL，拒绝远程连接；提交与授权/worker 控制通道分离，校验真实令牌、完整性级别及连接绑定，不能只信 Administrators 组名称或 PID。
- worker 注册使用受保护通道和一次性握手；客户端也验证服务端，避免管道抢注。普通用户不得创建授权、续期或替换策略。
- 任意管理员代码可持久化、修改系统甚至干扰执行器；期限、Job Object、日志不是恶意管理员代码的隔离。无法承诺抵抗已经控制同用户客户端的攻击者。
- 使用受保护绝对路径启动 pwsh，NoProfile/NonInteractive、明确工作目录及环境；普通构建仍以普通权限运行，不能把所有访问拒绝自动升级。
- 日志记录身份、授权、摘要、脚本哈希、退出状态和脱敏输出；不默认保存脚本全文。执行原文受限临时保存，结束清理，崩溃遗留清理亦需覆盖。秘密用凭据引用或运行时受控注入，不进入命令行。
- 更新先停止接收新任务并处理在途任务，再替换程序；保留可回退版本。通用窗口失效；能力语义或策略版本变化的授权需重新确认。
- 卸载撤销授权、处理运行任务、停止并移除服务和执行器；日志保留由用户选择。不能清除任意脚本已造成的系统修改。

## 验收

连续合法操作仅一次主动 UAC；后台未授权请求不抢焦点且立即返回；取消 UAC 不重弹；过期/撤销/篡改/错误身份确实拒绝；锁屏、注销、重启行为与执行身份一致；请求重复不重复执行；崩溃未知结果不误报成功；普通操作保持普通权限；更新与卸载在有运行任务时行为明确。

待实测：Windows Administrator protection、标准账户使用其他管理员凭据、快速用户切换、profile 与网络凭证、企业策略/EDR、会话注销时 worker 清理。

## 讨论中修正的结论

- 不再采用先临时进程后常驻服务的阶段路线。
- 不由服务自动获取用户完整令牌并称其等价于 UAC 批准。
- 不把所有中完整性进程描述成自动获得管理员令牌；真实风险是获准客户端被劫持或冒用。
- 不把脚本入口哈希当成依赖固定或安全证明。
- 不默认永久授权、不设无依据的十二小时上限、不默认记录脚本全文。
- 不把服务跨重启恢复等同 Agent 工作流自动恢复。

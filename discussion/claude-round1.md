**说明**：按指令禁用工具，本轮只做文字讨论，不写计划文件，也不调用 ExitPlanMode。以下未经联网核实的内容都标为待验证。

**【赞同】**
1. 分离普通权限 MCP 与管理员执行器、授权由执行器最终裁决、Agent 不能续期、撤销与杀任务分开、"终止不等于回滚"、失败不自动提权重跑：这些都成立。
2. "工作目录和黑名单约束不了任意管理员脚本"应写进用户可见文档，不能只留在设计稿里。

**【反对 1：主代理没有正视的核心事实】**
同用户的恶意进程和 Agent 在内核看来是同一主体。管道 ACL 只能按用户 SID 授权。校验 GetNamedPipeClientProcessId 再比对映像路径也能被绕过：同用户可以注入或镂空 MCP 进程，也可以读取它内存里的令牌。所以 T2 授权的真实含义是：窗口期内，该用户所有中完整性进程都等同管理员。这和微软"UAC 不是安全边界"的立场一致。方案应如实承诺这一点，不要暗示能区分"合法 Agent"。

**【反对 2：审批 UI 必须走安全桌面】**
托盘或普通窗口的"批准"按钮可以被同用户进程用 SendInput 或 UIA 点击（同完整性级别下 UIPI 不拦截），等于没有审批。
- 结论：开通授权必须由用户主动运行一个提权的 approve 命令，借 UAC 的 consent.exe 安全桌面完成认证。
- 也就是说，UAC 不被消灭，而是从"后台随机弹出"变成"用户主动、每个窗口一次"。这个设计同时解决误触问题，因为焦点是用户自己预期的。

**【反对 3：身份选择过于笼统】**
"服务以 SYSTEM 执行"会丢失用户上下文：HKCU、用户配置文件、映射盘、网络凭证、用户环境变量、用户 PSModulePath。开发任务常常依赖这些，结果会出现"手动运行能成功，经执行器就失败"。

**【推荐决策：架构与身份】**
- 唯一形态：一个开机自启的 Windows 服务（LocalSystem）作为代理。安装、更新、卸载各需一次 UAC。不另设临时进程或计划任务路径，避免两套信任模型。
- 用户已登录时：服务用 WTSQueryUserToken 加 TokenLinkedToken 取得该用户的完整提权令牌，再 CreateProcessAsUser。这样保留用户上下文，等价于"该用户点了 UAC"。
- 用户注销或重启后未登录时：只执行声明为 `context=system` 的任务（无 HKCU、无用户网络凭证）。声明为 `context=user` 的任务进入排队，返回 `needs_session`，不偷偷降级为 SYSTEM 运行，也不保存用户密码。

**【推荐决策：授权档位】**
- **T0 结构化操作**：类型化动词加参数白名单，例如重启指定服务、启停指定计划任务、改指定注册表值。安装时一次性批准，永久有效、无需窗口，覆盖大部分无人值守需求。
  - 注意："固定配置修改"若能写入服务会加载的配置、路径或二进制位置，就是提权通道。T0 动词必须逐个审查，任何改 ImagePath、ACL、Run 键、计划任务动作的操作都不能进入 T0。
- **T1 固定脚本**：在提权的 approve 中审阅内容，再复制到 `ProgramData\<app>\scripts`（仅管理员可写），按 SHA256 固定。执行时用 `pwsh -NoProfile -NonInteractive`，PSModulePath 只含受保护目录，禁止相对路径 dot-source。授权在撤销前持续有效。
  - 不能承诺：脚本运行时读取的外部数据或调用的用户可写 exe 发生变化，依赖变更无法检测，需要在文档中注明。
- **T2 任意 PowerShell**：需要时间窗口，默认 2 小时，上限 12 小时（需在 approve 中显式勾选"整夜"），可随时一键撤销。明确告知用户：窗口期内整机等同已交出。
- 默认状态：T0 开启，T1 为空，T2 关闭。

**【推荐决策：边界行为】**
- **误触**：后台从不弹 UAC，只返回 needs_approval 并发一条 Toast（不抢焦点）。
- **离线 / 未批准**：任务留在队列，设 TTL（例如 24 小时）后自动过期，不堆积。
- **重启**：授权以绝对过期时间持久化在受保护目录。仅勾选"整夜"的 T2 授权能跨重启存活，否则重启即清空。
- **授权过期**：拒绝新任务。在途任务按各自的执行时限跑完，超时后终止进程树。
- **执行中断**（服务崩溃或重启）：任务标记为 interrupted，不自动重跑，由 Agent 用新的请求 ID 重新提交。非幂等操作由调用方负责。
- **重复请求**：同一 request_id 返回已有状态。
- **撤销**：只阻止新任务；杀任务另用 cancel。子进程放入 Job Object（KILL_ON_JOB_CLOSE），但这挡不住管理员脚本创建服务、计划任务或 WMI 订阅等持久化，需要在文档中注明。
- **更新**：提权安装器先停服务、排空队列、替换二进制，授权保留。
- **卸载**：撤销全部授权，删除服务、管道和状态目录，日志可选保留。

**【推荐决策：关键风险对策】**
- **服务二进制可写**：执行器不要用 Python 加用户 venv，因为解释器和 site-packages 一旦用户可写就是提权漏洞。执行器用 .NET 8 自包含单 exe，装在 Program Files，安装时校验 ACL。pwsh 用 Program Files 下的绝对路径调用。
- **UI 伪造**：所有授权只在提权进程中产生，普通进程只能请求、不能写授权文件或管道授权命令。
- **管道安全**：DACL 只允许 SYSTEM、Administrators 和目标用户 SID，加 `PIPE_REJECT_REMOTE_CLIENTS`。服务首先创建管道，防止抢注。
- **日志**：脱敏参数，但完整保留 T2 脚本正文，供事后审计。

**【技术栈与 MCP 契约】**
- 技术栈：MCP 用 Python（沿用用户现有 MCP 工程风格，常量集中、类与函数分文件），执行器用 C#/.NET 服务，approve 为同一 exe 的提权子命令。
- MCP 工具（Agent 没有任何批准或续期工具）：
  - `admin_submit(kind=op|script|ps, op/args|script_id|code, context=user|system, timeout_s, request_id, reason)`，返回 `{id, status: queued|needs_approval|needs_session|running|done|failed|rejected|interrupted}`
  - `admin_status(id)`
  - `admin_output(id, tail)`
  - `admin_cancel(id)`
  - `admin_grants()`（只读）
  - `admin_ops()`：列出 T0 动词及参数模式，供 Agent 优先选择结构化操作。

**【待验证】**
1. Windows 11 的"Administrator protection"（影子管理员账户）启用后，TokenLinkedToken 的语义和配置文件路径会变化。需确认用户系统版本和该策略状态，这会直接影响"用户上下文"方案。
2. CreateProcessAsUser 使用提权链接令牌时，网络驱动器映射和 Kerberos/NTLM 单点登录是否按预期工作。
3. 用户是否需要在锁屏状态下执行 `context=user` 任务。锁屏时会话仍在，应该可行，需要实测。
4. 企业组策略或 EDR 是否拦截由服务派生的 pwsh。

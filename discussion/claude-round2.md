**接受 / 仍有保留**

1. **同用户风险：接受你的表述，补充一点。** 通用窗口开启期间，同用户恶意代码不需要窃取任何东西，只要冒用获准客户端（例如向 MCP 提交请求或注入宿主），就能执行任意管理员操作。文档应写明这个具体后果，否则用户会把"误用防护"理解成隔离。最终措辞："无法抵抗已控制同用户进程的攻击者；通用窗口期间其可经合法路径执行任意管理员代码；任意管理员脚本可持久化，卸载不清除。"
2. **approve 流程：完全接受。** UAC 只认证"启动 approve.exe"。approve 提权后从受保护目录加载请求快照，按快照的 hash 展示并显式确认，不再读取调用方传来的内容。我上轮把自定义界面说成位于安全桌面，表述错误，撤回。
3. **执行身份：接受你的方案，放弃 broker 自取链接令牌。** 理由如下：
   - 自取令牌在标准账户、异账户凭据、Administrator protection 下语义各不相同，而且 profile 和环境不会自动加载，难以如实承诺"等同用户提权"。
   - 补充设计：用户批准后，由 UAC 启动的管理员 worker 主动连接 broker 的仅 SYSTEM/Administrators 可访问的管道，拉取任务。worker 自己不监听，避免多出一个可被中完整性进程连接的端点。
   - worker 随会话结束而退出，之后 user-elevated 任务返回 `needs_session`，不降级为 SYSTEM。
4. **授权期限：接受。** 不设无依据的上限，也不把"整夜"与"跨重启"绑定。保留一条建议：approve 让用户直接选结束时间，不预填长时限。
5. **固定脚本：接受，保留一个窄例外。** 例外条件：脚本自包含、从管理员保护快照运行，且只调用系统目录下的二进制和受保护模块。只有满足这些条件才可归入"受审阅脚本"档，否则一律按通用管理员权限授权。即使归入该档，也只代表"用户审阅过的管理员代码"，不代表安全。
6. **日志、更新、卸载、needs_approval 状态、outcome_unknown、Job Object 局限、不做调度器（你的第 6–8 点）：全部接受，无异议。**

**统一设计**

- **组件**
  - 普通权限 Python MCP，只负责提交和查询。
  - .NET broker 服务（LocalSystem，Program Files，安装时校验 ACL），负责策略、队列和授权裁决。
  - approve.exe，经 UAC 提权，负责审阅并签发授权。
  - 管理员 worker，由 approve 在用户会话中启动，执行 user-elevated 任务。
  - SYSTEM 执行器，由 broker 派生，仅执行显式批准的 machine 任务。
- **授权档位**（每档都要用户在 approve 中单独主动选择，安装后默认全部为空）
  - 结构化操作：类型化参数白名单，排除任何改服务路径、ACL、自启项、计划任务动作的能力。可持久授权，默认跨重启恢复。
  - 受审阅脚本：须满足第 5 点的例外条件，授权持久直到撤销。
  - 通用管理员 PowerShell：时间窗口默认 2 小时，可设为用户离开的时长，可随时撤销；默认不跨重启。
- **执行身份**
  - user-elevated：只在 worker 在线时执行。
  - system：只执行显式标注为机器任务的请求。
  - 不保存密码，不自取用户令牌，不跨上下文降级。
- **请求生命周期**
  - 未获授权：返回 `needs_approval`，请求不入执行队列，只发不抢焦点的 Toast，过 TTL 后失效。
  - 用户运行 approve：确认快照后，broker 复核 TTL、目标和内容 hash，一致才入队。
  - 状态枚举：`queued`、`running`、`done`、`failed`、`rejected`、`needs_session`、`cancelled`、`outcome_unknown`。
  - 出现 `outcome_unknown` 时，必须先核验实际状态，禁止直接换新 ID 重试非幂等操作。同一 request_id 重复提交返回原状态。
- **撤销与中止**
  - 撤销只阻止新任务；cancel 终止 Job 内进程树，但不保证终止经服务或计划任务派生的工作，也不回滚。
  - 到期后拒绝新任务，在途任务按其执行时限处理。
- **更新与卸载**
  - 更新经提权安装器完成。策略或动作语义版本变化时，作废对应授权；通用窗口一律作废。
  - 卸载移除服务、管道和状态目录，并声明不清除脚本造成的持久化。
- **日志**：记录 hash、脱敏摘要、身份、档位和结果。执行原文放在受限临时区，任务结束后删除。保存全文审计需要显式配置。
- **MCP 工具**：`admin_submit`、`admin_status`、`admin_output`、`admin_cancel`、`admin_grants`（只读）、`admin_ops`。不提供批准或续期工具。broker 只管理已授权任务，不负责恢复 Agent，也不做通用调度。
- **待验证**
  - worker 与 broker 的互认方式（approve 经受保护通道下发一次性凭据）在注销、快速用户切换下的行为。
  - Administrator protection 下 worker 的 profile、网络凭据实际表现。
  - EDR 或组策略是否拦截服务派生的 pwsh。

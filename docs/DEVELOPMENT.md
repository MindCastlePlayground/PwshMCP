# 开发与验收计划

## 架构与责任
- Shared：强类型 DTO、协议常量、命名管道客户端（主代理）。
- Execution：fresh 环境、独立 PowerShell、显式持久会话、取消与输出（独立固定范围 worker）。
- Host：本地管道 broker、授权、管理员 worker、Windows 服务入口、MCP stdio（主代理）。
- Tray：原生 Windows 托盘、请求/授权/任务窗口、提权审批、状态图标与全部用户文案（Claude）。
- scripts/tests：构建发布、服务安装卸载、端到端验收（主代理整合）。

## 工作顺序（同一完整交付，不是分批产品）
固定基线及协议 → 并行实现 UI 与执行库、主代理实现 broker/MCP → 接口需求即时对齐 → 集成构建 → 自动测试 → 原生 UI 视觉及真实权限路径验收 → 记录未验证边界与交付。

## 验收矩阵
协议/重复请求/撤销/身份校验；fresh 环境修改删除与 PATH；任务隔离与持久会话重建；MCP initialize/tools/list/call；托盘待办不抢焦点、授权列表和拒绝/撤销；一次 UAC 多次管理员任务；服务重启与未知结果；安装卸载。

禁止为测试关闭 UAC、创建安全软件排除或泄露凭证。服务安装与产品提权必须走用户可见的主动入口，不由后台开发自动弹窗。

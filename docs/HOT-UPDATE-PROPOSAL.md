# PwshMCP 无缝热更新方案（待审阅）

日期：2026-11-04。状态：设计提案，尚未实施。依据为当前仓库源码及 TaskHub daemon 文档；下文时间指标是验收目标，尚无实测数据。

## 建议与用户体验

采用“固定入口 + 并存版本目录 + 旧任务留在旧执行器”的更新方式。界面可以单独更新，后台任务继续运行；执行器更新后，新任务使用新版，正在执行的任务和已有 PowerShell 会话继续使用旧版，结束后释放旧进程。

第一阶段实现界面独立更新及执行器逐步切换；Broker 更新先安排在空闲时。第二阶段再实现 Broker 的状态交接，达到有任务运行时也能切换。两阶段分别验收，第一阶段的交付称为“界面与执行器平滑更新”，完整无缝能力以第二阶段验收为准。

“无缝”的具体目标：

- 正在运行的命令不中断、不重复执行；命令正文、输出、错误和任务编号保持可查。
- 已连接 Agent 的 MCP stdio 连接持续存在，客户端配置路径保持不变。
- 显式 PowerShell 会话中的变量、模块和当前目录保留；这些会话固定到旧 Worker，关闭或显式重置后才迁移。
- 授权的客户端、用户、登录会话、范围与原到期时间保持不变；注销、到期和撤销继续立即生效。
- 托盘窗口保留所选任务、页签、语言、窗口位置与输出展开状态；输出正文从原任务重新读取，更新记录不保存正文或秘密。
- 候选启动失败时原版本继续服务；切换后故障按数据兼容条件回退。

## 当前实现为何无法直接支持

| 现有机制 | 对更新的实际影响 | 依据 |
| --- | --- | --- |
| 桌面安装器要求关闭安装目录内所有进程，再覆盖文件 | MCP、托盘、Worker 共用目录，整包替换会影响现有连接和执行 | `scripts/install-desktop.ps1` |
| 托盘可启动并拥有 Broker；TaskHub 管理托盘进程树 | 停止托盘可能同时终止 Broker；仅重启界面并无任务连续性保证 | `Tray/Monitor.cs`、`docs/TASKHUB.md` |
| Broker.Restore 在启动时结束活跃授权，把非终态任务设为 OutcomeUnknown | 普通重启会丢失任务连续状态，旧授权需要重新建立 | `Host/Broker.cs` |
| StateStore 保存摘要，清空代码、环境及输出；完成后才归档完整历史 | 当前状态文件不足以重建排队命令或运行现场 | `Host/StateStore.cs`、`HistoryStore.cs` |
| Worker 的运行中轮询失败会退出，finally 取消任务；结果发送失败缺少持久重投 | Broker 切换窗口可能中断任务或丢失完成结果 | `Host/Worker.cs` |
| MCP 进程启动普通 Worker，结束时杀掉其进程树 | 替换 MCP 进程会影响 Worker 与持久会话 | `Host/Mcp.cs` |
| BrokerClient 校验服务端完整 exe 路径；Peer 从真实管道对端获取身份 | 直接增加代理或换版本目录会改变信任边界，须显式设计身份传递 | `Shared/Protocol.cs`、`Host/Peer.cs` |

源码路径前缀为 `src/PwshMcp.`。历史状态目录继续沿用当前账户对应的 LocalAppData/ProgramData；不得在更新中顺便切换运行账户，影响 DPAPI 解密与授权归属。

## 目标结构

### 1. 固定入口与版本目录

保留现有客户端配置中的 `C:\Program Files\PwshMCP\PwshMcp.Host.exe` 路径，将其逐步改为稳定的 MCP 入口。该入口负责协议连接和转发，业务代码从 `versions/<release>/` 启动。托盘使用固定启动器，TaskHub 只监管启动器，不再把执行核心放在托盘进程树内。

每个发布版本进入独立只读目录，运行中的版本不覆盖。一个受保护的当前版本记录保存默认版本和上一个可用版本；新进程读取它，已运行进程继续使用原目录。旧版有活跃 Worker、会话或尚未确认的结果时保留，引用清零后清理。

更新器使用现有明确授权的管理员通道安装程序文件；发布元数据与制品须能验证来源及完整性。不能让普通用户可写的配置指定任意管理员可执行路径。稳定入口自身采用空闲维护更新，或在下一次客户端建立连接时使用新版；不尝试更换已连接进程内的协议宿主。

### 2. 托盘与执行核心分离

Broker 使用独立生命周期，托盘退出、崩溃或 TaskHub 重启 UI 均不结束 Broker/Worker。保持现有普通用户 Broker 和独立管理员协调器的权限划分；不为热更新把所有任务改到 SYSTEM。

更新时先预加载候选 UI 的资源与连接，再保存非敏感视图状态。旧 UI 释放单实例锁并退出，新 UI 接管锁、恢复窗口和选择。锁交接失败则原 UI 保留或恢复；同时只允许一个托盘图标接收操作。界面闪动目标不超过 2 秒，后台执行持续运行。WPF 控件树不在原进程内替换程序集，以免绑定、静态资源和事件引用跨版本混杂。

### 3. 执行器逐步切换

Broker 记录 Worker 的版本、进程启动标识及可处理的协议版本。切换后，新的独立任务分配给新版 Worker；已有任务仍由原 Worker 完成。已有命名会话固定绑定原 Worker，新的会话默认使用新版。

运行旧任务的 Worker 停止领取新的无会话任务，但继续接收属于其已有会话的命令。授权到期或撤销时，旧版和新版 Worker 同时遵循同一授权状态。使用旧版本会话的数量可在诊断中查看，不自动重跑会话初始化命令或复制无法序列化的 PowerShell 对象。

### 4. Broker 连续切换（第二阶段）

先扩展协议，增加版本协商、执行领取凭据、请求幂等键和持久完成回执。Worker 在交接窗口保留运行任务；通信恢复后，提交同一份结果直至 Broker 确认，Broker 按任务和领取凭据去重。取消与授权失效仍通过心跳确认；失联容忍必须有界，超过期限按原安全语义停止授权任务。候选交接目标小于 2 秒，建议初始断联容忍上限 5 秒，并在测试中覆盖撤销延迟；需要更长窗口时提前排空受影响任务。

新增受 ACL 与 DPAPI 保护的任务日志，记录已接受但尚未结束的任务定义、归属、领取记录、取消/撤销事件和完成回执。任务中的环境秘密按最小需要加密保存，终态确认后按保留策略清除。用户代码可能具有外部副作用，因此日志只保证“已接受请求不丢失”和“同一任务不被重新领取执行”；执行进程崩溃且结果无法确认时仍标记结果未知，由使用者检查实际效果。

交接顺序：准备候选 → 检查协议/数据可读性 → 暂停旧 Broker 领取新任务 → 刷新日志并取得唯一写入权交接点 → 候选取得写入权 → 切换连接目标 → Worker 重连核对领取记录 → 恢复领取。任何时刻只有一个 Broker 能接收并确认写入；旧 Broker 失去写入权后只允许排空已在途响应或退出。切换中对新提交进行短暂排队，超时返回可重试状态，同一请求沿用幂等键。

为保留真实调用方身份，优先让客户端直接连接选定版本的 Broker 管道；通过受保护的服务发现记录取得管道及允许的 exe 路径，并核验进程身份、路径与安装目录权限。兼容旧固定管道需要独立桥接设计：转发时由可信入口获取真实令牌信息，通过仅入口可连接的内部通道传给 Broker；不接受客户端自报 SID、权限或 PID。应先完成身份与授权隔离测试，再启用桥接。最终选直接连接还是兼容桥接，须在实现前基于已有客户端升级成本做一次具体取舍。

首次从当前版本迁入上述协议需要维护窗口：旧 Worker 没有重连与结果重投能力。先等待已有任务结束、确认持久会话处理方式，再升级基础版本；以后才具备连续切换条件。

## 更新、失败和回退

| 时机 | 处理 |
| --- | --- |
| 下载/解包/候选自检失败 | 当前入口与运行版本保持原状，报告失败原因 |
| UI 候选无法连接或恢复窗口 | 启动原 UI，后台任务继续运行 |
| 执行器切换后新任务失败 | 将新任务默认版本切回旧版；已开始的新版任务继续由其原进程处理，不自动重跑 |
| Broker 交接前失败 | 旧 Broker 恢复领取新任务 |
| Broker 取得写入权后失败 | 按日志恢复到兼容旧版，或由同版恢复进程接续；先确认旧实例失去写入权，防止双写 |
| 数据格式已升级且旧版无法读取 | 保留新版恢复入口，前向修复；仅在明确可还原且没有新写入时恢复快照 |
| 更新器中途退出或机器重启 | 读取受保护的更新阶段记录，核对真实进程与日志所有者后恢复；不依据阶段文件单独宣告成功 |

版本记录、任务日志及更新阶段记录都有明确机器消费者，仅保存恢复所需字段。错误日志不写命令正文、环境变量值或认证信息。

## 分阶段交付和验收

| 阶段 | 交付 | 必须通过的真实场景 |
| --- | --- | --- |
| A：安装基础 | 固定入口、并存版本目录、安装/回退工具；一次维护迁移 | 现有 Agent 配置可用；失败候选不影响当前版本；回退后能执行普通和管理员任务 |
| B：UI 与 Worker | Broker 独立生命周期、窗口状态交接、Worker 版本路由和会话绑定 | 长任务执行时更新 UI，任务与输出完整；旧会话变量仍在；新任务用新版；撤销同时作用于新旧 Worker |
| C：Broker | 持久日志、完成回执、唯一写入权交接、身份验证和重连 | 执行中切 Broker 任务不中断；切换边界提交/取消/完成无丢失及重复；未确认结果可重投；断联超时、注销和撤销符合权限规则 |

验收使用可观察副作用计数的任务证明只执行一次；在完成前、发送结果时、Broker 确认后分别切换或终止候选，验证完整命令、输出和错误。包括多客户端并发、普通/管理员任务、多个命名会话及 TaskHub 实际守护路径。回退按“切换前失败”和“切换后已有新任务”分别检查。通过的当前阶段检查直接复用。

建议审阅重点：接受按 A→B→C 分阶段交付；接受长期命名会话保留旧执行器；接受首次迁移和稳定入口自身升级安排空闲维护窗口。批准方案后再开始热更新实现，本次修复安装仍按现有机制执行。

# PwshMCP 托盘 UI 0.4.0：主窗口内联批准

## 目标
安装时只弹一次 UAC。之后的提权批准都在现有托盘主窗口内完成：选择有效期 → 批准，不开新窗口，不再弹 UAC。

## 交互
- **请求详情 → 「批准此请求」卡片**（仅当执行器就绪时显示）：
  - 说明权限范围：仅限此客户端在本次 Windows 登录中，每条命令都在全新的 PowerShell 环境中运行，不隔离也不撤销更改。客户端名称仅用于显示，不是身份凭据。没有持久的自动批准。
  - 有效期四选一（直到注销/1 小时/4 小时/今天结束前），以 2×2 单选格呈现，带访问键。下方的进度条显示截止时间和剩余时长；选“直到注销”时附加说明。
- **底栏**：在批准按钮旁回显“有效期：…”，点击后滚动到卡片并聚焦当前选项。发送中，按钮显示旋转图标和“正在批准…”，同时锁定选项并禁止重复提交。失败信息以红色就地显示，请求保持待批准，可直接重试。
- **执行器状态**：页头显示状态标签（检查中/就绪/离线/需修复），悬停可查看详情。状态不可用时：
  - 卡片换成琥珀色提示区，给出安装或修复建议（`scripts\install-desktop.ps1`）和“不会弹出 UAC”的说明，并提供“重新检查”按钮和上次检查时间。
  - 批准与重启按钮禁用。
  - 不会自动回退到 runas。
- **批准成功**：只有当 `Grant.State == Active` 时才视为成功。随后切换到“授权”页并选中该授权，提示“已批准”。如果返回 Ok 但状态不是 Active，按失败显示。
- 恢复执行器（重启）走 `Op.Resume`，处理方式与批准相同。

## 实现
- `Coord.cs`：
  - 执行器状态轮询独立于代理监视器。就绪时每 5 秒、离线时每 3 秒检查一次，失败可立即重试，不阻塞 UI。
  - `Send` 负责发出 `Op.Approve(Id, ExpiresAt UTC)` 和 `Op.Resume`。“直到注销”不发送 ExpiresAt。
  - 异常映射：`UnauthorizedAccess` → 需修复（服务端不受信），超时/IO/取消 → 离线。
  - 传输层可注入，供自测使用。
- `Fmt.Err` 把 `AdminNames` 的错误码（Offline/Forbidden/Invalid/Protected/Worker）映射为中英文文案。
- 常规 `MainVm` 路径不再调用 `Launch.Elevated`。`ApproveWindow`/`ApproveVm` 只保留给显式启动的旧流程。有效期计算已抽到 `Lives`，供两条流程共用。
- 样式：`K.Issue`（批准卡片）、`K.Pick`（紧凑单选）、`K.Blocked`（琥珀提示区）、`K.BusyTpl`（盾牌/旋转图标）。界面延续深色主题，不显示 ID。
- 版本 0.4.0。所有文案位于 `Copy.Inline`/`Copy.Gate`，键名位于 `K`/`Report`。

## 自测（`--render-check artifacts/ui-0.4.0`，190 项，0 失败）
使用伪造的传输层，不调用 `Coord.Start()`，不走真实管道，也不触发 UAC。中英文各测一遍，宽度为 720 和 1000：
- 就绪：批准可用。卡片可滚动到达，渲染文件为 `gate-*-inline-card-*`。
- 离线/需修复：批准禁用，提供重新检查。渲染文件为 `gate-*-down-*`、`gate-*-broken-*`。
- 被拒（Forbidden）：已发送的 Op/Id/ExpiresAt 约为 1 小时；错误就地显示，可重试。渲染文件为 `inline-*-failed-*`。
- 返回 Ok 但状态为 Pending：不判定为批准成功。
- 直到注销：不发送 ExpiresAt；返回 Active 时接受。
- 发送中：重复提交和切换有效期都被阻止。渲染文件为 `inline-*-sent-*`。
- 文案检查：占位符和访问键在两种语言间一致。

## 遗留与契约说明
- 未用真实管道、真实执行器或 UAC 验证，需由上级完成正式构建、安装和验收。
- 契约只接受安装目录下的 `PwshMcp.Tray.exe`。开发构建的托盘发出批准会收到 Forbidden，界面会如实提示“请从安装位置打开”，不会伪装成功。
- 离线/需修复的详情是固定建议文案。契约的 Status 只返回 Ready/错误码，没有更细的诊断字段；如需精确原因，需要扩展 `AdminResponse`。
- 旧的 `ApproveWindow` 仍会经 UAC 启动，仅限显式命令行使用，常规路径不会进入。

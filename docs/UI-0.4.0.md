# PwshMCP 托盘 UI 0.4.0：主窗口内联批准

## 目标
安装时只弹一次 UAC。之后的提权批准都在现有托盘主窗口内完成：选择有效期 → 批准，不开新窗口，不再弹 UAC。

## 交互
- **请求详情 → 「批准此请求」卡片**（仅当执行器就绪时显示）：
  - 说明权限范围：仅限此客户端在本次 Windows 登录中，每条命令都在全新的 PowerShell 环境中运行，不隔离也不撤销更改。客户端名称仅用于显示，不是身份凭据。没有持久的自动批准。
  - 页面内不再放有效期选择器，卡片只保留权限范围说明。
- **底栏有效期链接 → 锚定弹出层**：左下角“有效期：直到注销 ⌃”点击后，在链接正上方弹出轻量浮层（`Popup`，Placement=Top，StaysOpen=false）。它不是二次确认，不滚动页面，也不追加卡片。
  - 浮层内容：标题“有效期”；四个选项（直到注销/1 小时/4 小时/今天结束前），带访问键，并以小字预览截止时间（“注销或重启时结束，锁屏不会”/“至 10月28日 21:05”）；当前选项高亮；底部一行范围说明“适用于 {客户端} 在本次 Windows 登录中发送的所有命令，不只是此任务。”
  - 选择后更新底栏文字并关闭浮层，焦点回到链接。批准仍是单击，经现有 AdminClient 发送，不弹 UAC，也不再确认。
  - 键盘：打开后聚焦当前选项，方向键在选项间循环，Enter 选中，Esc 关闭（不会触发窗口的 Esc 隐藏），Tab 在浮层内循环。点击外部也会关闭，且同一次点击不会重新打开。
  - 以下情况自动关闭，不留残留浮层：切换选中请求或标签页、请求不再待批准或不可编辑、进入发送中、窗口隐藏/最小化/失焦/移动/缩放、切换语言（旧窗口 Release）。发送中或执行器离线/需修复时，链接被隐藏或禁用，`Open` 也会拒绝。
- **底栏**：发送中，批准按钮显示旋转图标和“正在批准…”，并禁止重复提交。失败信息以红色就地显示，请求保持待批准，可直接重试。
- **执行器状态**：页头显示状态标签（检查中/就绪/离线/需修复），悬停可查看详情。状态不可用时：
  - 卡片换成琥珀色提示区，给出安装或修复建议（`scripts\install-desktop.ps1`）和“不会弹出 UAC”的说明，并提供“重新检查”按钮和上次检查时间。
  - 批准与重启按钮禁用。
  - 不会自动回退到 runas。
- **批准成功**：只有当 `Grant.State == Active` 时才视为成功。随后切换到“授权”页并选中该授权，提示“已批准”。如果返回 Ok 但状态不是 Active，按失败显示。
- 恢复执行器（重启）走 `Op.Resume`，处理方式与批准相同。

## 实现
- `Coord.cs`：
  - 执行器状态轮询独立于代理监视器。就绪时每 5 秒、离线时每 3 秒检查一次，失败可立即重试，不阻塞 UI。
  - `Send` 负责发出 `Op.Approve(Id, ExpiresAt UTC)` 和 `Op.Resume`。“直到注销”不发送 ExpiresAt。
  - 异常映射：`UnauthorizedAccess` → 需修复（服务端不受信），超时/IO/取消 → 离线。
  - 传输层可注入，供自测使用。
- `Fmt.Err` 把 `AdminNames` 的错误码（Offline/Forbidden/Invalid/Protected/Worker）映射为中英文文案。
- 常规 `MainVm` 路径不再调用 `Launch.Elevated`。`ApproveWindow`/`ApproveVm` 只保留给显式启动的旧流程。有效期计算已抽到 `Lives`，供两条流程共用。
- 样式：`K.Issue`（批准卡片）、`K.Pop`（浮层卡片，宽 336，带阴影）、`K.Pick`（浮层列表行：悬停/选中/键盘焦点三态）、`K.Blocked`（琥珀提示区）、`K.BusyTpl`（盾牌/旋转图标）。界面延续深色主题，不显示 ID。
- 版本 0.4.0。所有文案位于 `Copy.Inline`/`Copy.Gate`，键名位于 `K`/`Report`。

## 自测（`dotnet src/PwshMcp.Tray/bin/Debug/net8.0-windows/PwshMcp.Tray.dll --render-check artifacts/ui-popup-0.4.0`，250 项，0 失败，见 `ui-selftest.txt`）
使用伪造的传输层，不调用 `Coord.Start()`，不走真实管道，也不触发 UAC。浮层显隐经 `MainWindow.Pop` 接缝替换，不创建弹出窗口句柄。中英文各测一遍：
- 页面：没有 `K.Pick` 单选，也没有“有效期”选择器文字。渲染文件为 `gate-*-inline-720`。
- 浮层：静止时关闭；StaysOpen=false、Placement=Top；关闭时 Esc 不被浮层吞掉。按 AutomationId 点击链接后打开，绑定到当前选中请求，默认选中“直到注销”。
- 浮层内容：取真实浮层卡片渲染，检查无裁切、文案共享、截止时间预览与范围说明齐全、四个选项都在。卡片叠放在链接上方，宽度 720/1000/1400 下均位于窗口内。渲染文件为 `popup-*-{720,1000,1400}`。
- 选择 4 小时：浮层关闭，底栏文字等于 `Picked`，Until 约为 4 小时。渲染文件为 `popup-*-picked-*`。重新打开时选中当前项；Esc 关闭并保留选择；Enter 选中焦点项。
- 切换标签页或取消选中时关闭，且旧链接无法重新打开；Release（换语言路径）关闭已打开的浮层；进入发送中时关闭、链接禁用、`Open` 被拒。
- 在浮层中选 1 小时后批准：发送的 ExpiresAt 约为 1 小时。
- 就绪：批准可用。
- 离线/需修复：批准禁用，提供重新检查；有效期链接隐藏，浮层拒绝打开。渲染文件为 `gate-*-down-*`、`gate-*-broken-*`。
- 被拒（Forbidden）：已发送的 Op/Id/ExpiresAt 约为 1 小时；错误就地显示，可重试。渲染文件为 `inline-*-failed-*`。
- 返回 Ok 但状态为 Pending：不判定为批准成功。
- 直到注销：不发送 ExpiresAt；返回 Active 时接受。
- 发送中：重复提交和切换有效期都被阻止。渲染文件为 `inline-*-sent-*`。
- 文案检查：占位符和访问键在两种语言间一致。

## 授权列表“已结束”分组标题
- 问题：旧实现把“已结束”标签放在第一条已结束授权的行模板里，标题落在该行卡片的背景、悬停和选中区域内，看起来只属于这一条。
- 实现：`MainWindow.Group` 在 `Access` 的默认 `ListCollectionView` 上按 `GrantVm.IsEnded` 分组。组名顺序固定为 false（生效中）→ true（已结束），开启 live grouping，授权过期或被撤销时会自动移入“已结束”组。组内保留 `MainVm` 原有排序。`accList` 的 `GroupStyle`（`HidesIfEmpty`）只给 true 组显示标题：两侧是 1px 的 `K.Line` 细线，按宽度自适应，中间是居中的 `K.Label` 文案 `Copy.Tabs.Ended`（——已结束—— / ——Ended——）。标题挂在 GroupItem 上，不属于任何 `ListBoxItem`，不可聚焦，不参与命中测试；GroupItem 也不可聚焦，不是 Tab 停靠点。已删除 `GrantVm.Divider` 及其计算逻辑，后端无改动。
- 细线关闭了 layout rounding：1px 线居中在半像素位置时，会被取整成 0 高，导致不绘制（首次渲染的“仅已结束”截图里确实缺线）。现在改由 `SnapsToDevicePixels` 对齐像素。
- 自测：`Check.Ended` 中英文各跑三种列表：混合（2 条生效中、3 条已结束）、仅已结束、仅生效中，宽度 720/1000。检查项：标题恰好 1 个（仅生效中为 0）；标题不在 ListBoxItem 内、位于不可聚焦的 GroupItem 上、不可命中；行数等于授权数，顺序与源一致；生效中的行都在标题上方，已结束的行都在下方；选中已结束授权时只有它那一行被选中，且 `ContainerFromItem` 能取到容器（`FocusList` 依赖它）；标题只显示当前语言。诊断构建运行 `--render-check artifacts/ui-ended-label/render`：308 项，0 失败。渲染文件为 `ended-{zh,en}-{mixed,ended-only,active-only}-{720,1000}.png`。逐像素检查确认，所有含已结束授权的截图都有 `#313640` 细线，仅生效中的截图没有。
- 未验证：真实窗口中的键盘上下移动和 Tab 焦点（离线时没有输入焦点）；读屏对分组的播报；运行中授权状态变化时的 live grouping 移动（只测了重新载入快照）；125% 缩放下细线的实际效果。

## 滚动条、滚动区域与边界
- 问题：所有滚动区域都使用 WPF 默认的 17px 灰色 Aero 滚动条，在深色主题下很突兀。滚动条出现时，内容会被挤窄 17px，导致重新换行和跳动。列表行的焦点框（`pm.focusVisual`，外扩 3px）被 ScrollContentPresenter 的装饰层裁掉。“授权”组内的行被默认 GroupItem 模板缩进 5px，与其他标签页不对齐。720px 时详情列 `MinWidth=400` 使总宽 745px，超出窗口，详情区右侧 25px（含滚动条）落在屏幕外。
- 滚动条（`Styles.xaml` 隐式 `ScrollBar` 样式，全应用通用，含代码块和旧批准窗口）：10px 槽位，无箭头按钮，点击轨道翻页。拇指是 4px 的 `K.Muted` 圆角条（不透明度 0.42）；指针悬停在槽位任意位置时变宽到 8px，不透明度 0.7；拖动时改用 `K.Accent`，不透明度 1。整个 10px 槽宽都是命中区域；拇指最短 24px。横向滚动条使用同一套规则。
- `K.Scroll`（ScrollViewer 样式）：可见性为 Auto 的滚动条在隐藏时也保留 10px 槽位（Hidden 而不是 Collapsed），所以内容出现或不再溢出时不会重排。槽位从各处原有的外边距中扣除，不挤占内容：
  - 详情页（请求/授权/任务）：StackPanel 外边距 `32,28,32,28` → `32,28,22,28`，加上 10px 槽位仍为 32。不溢出时内容宽度不变；溢出时内容不再被挤窄 17px。
  - 代码块 `CodeView`：RichTextBox 外边距 `12,8,12,10` → `12,8,2,10`，加 10 槽位，换行宽度不变。
  - 输出/错误流 `K.CodeBox`：内边距 `12,10` → `12,10,2,0`，右侧和底部各加 10 槽位，文字内缩仍为 12/10。横向滚动只在 NoWrap 的输出框出现，换行内容不会产生横向滚动。
  - 设置 `Tag=Names.Rules` 时，视口上下边缘显示 1px `K.Line` 细线，表示这一侧还有内容（转换器 `All.Above`/`All.Below`）。只有侧栏列表开启；详情区上下已有页头线和底栏线，不重复。
- `K.List`（三个侧栏 ListBox 共用）：视口向左扩 4px、上下各扩 6px、向右扩 12px，占用侧栏已有的外边距（16/12/12），滚动条贴着分隔线。内边距 `4,6,4,6` 在可滚动区域内，可容下 3px 焦点框和行的圆角。保留默认模板的规则：分组且不虚拟化时按像素滚动。任务列表的虚拟化、选择、键盘和滚轮行为未改。
- “授权”分组：GroupItem 改用无缩进模板（标题 `PART_Header` 加 `ItemsPresenter`）。标题仍挂在 GroupItem 上，位于卡片外，现有 Ended 检查全部通过。
- 详情列 `MinWidth` 400 → 352（720px 窗口客户区约 704px，减去侧栏 340 和分隔线 5）：720px 时详情滚动条和底栏按钮回到窗口内。
- 实测尺寸（中/英）：行高不变，中文 55.2px，英文 56.8px；行内边距 12,10、字号和 MinHeight 未改。行宽：
  - 请求/任务：改前不溢出时 310px，溢出时 293px → 改后两种情况都是 310px。
  - 授权：改前 305px，溢出时 288px（5px 缩进）→ 改后 310px。
  - 行左缘 x=16，与标签条对齐（改前 17，授权 22）。
  - 侧栏视口 318×538（1000px 窗口）。
  - 详情区宽度方面，只有 720px 时内容区比改前窄 25px，但那 25px 原本就在窗口外。
- 自测（`--render-check artifacts/ui-scroll/render`：789 项，0 失败，其中 scroll 331 项）：新增 `Check.Scrolls`，用 24 条请求、30 条授权（含已结束分组）、40 个任务，中英文，宽度 720/1000/1400，滚动到顶部和底部，分别选中首行和末行。检查项：
  - 列表溢出，滚动条为主题样式，宽 10px。
  - 行宽等于短列表不溢出时的宽度（310），行高不变。
  - 行左缘与标签条对齐。
  - 每行左右都留出焦点框空间，滚动条不压行。
  - 选中的首行/末行完整显示，焦点框在视口内。
  - 边缘细线只在对应方向还有内容时显示。
  - 详情区：始终保留槽位，滚动条在窗口内，不压底栏，滚到底部能看到内容末尾。
  - `Wraps` 另检查代码块使用 `K.Scroll`。
  - 渲染文件为 `scroll-{zh,en}-{Requests,Access,Tasks}-{top,bottom}-{720,1000,1400}.png` 和 `detail-*-bottom-*.png`。
- 未验证：真实窗口中的悬停、拖动状态和拇指变宽（离线渲染只有静止态）；真实键盘焦点框（离线没有焦点，只做几何检查）；滚轮、触控板和触摸平移；125%/150% 缩放；高对比度主题；浅色主题下的拇指对比度（Muted 0.42）。

## 遗留与契约说明
- 未用真实管道、真实执行器或 UAC 验证，需由上级完成正式构建、安装和验收。
- 浮层的以下行为只在离线模型中验证过，没有在真实窗口中验证：弹出窗口的实际定位、点击外部关闭及防止重开的 300ms 保护、真实焦点移动与归还、淡入动画、实际显示器 125% 缩放、读屏输出。720px 下英文底栏文字会换成两行。
- 契约只接受安装目录下的 `PwshMcp.Tray.exe`。开发构建的托盘发出批准会收到 Forbidden，界面会如实提示“请从安装位置打开”，不会伪装成功。
- 离线/需修复的详情是固定建议文案。契约的 Status 只返回 Ready/错误码，没有更细的诊断字段；如需精确原因，需要扩展 `AdminResponse`。
- 旧的 `ApproveWindow` 仍会经 UAC 启动，仅限显式命令行使用，常规路径不会进入。
